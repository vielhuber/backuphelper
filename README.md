# 💾 backuphelper 💾

backuphelper is a bash script that writes rotating `tar.gz` backups from one yaml config: local paths, the files of git checkouts that are not in git and the output of any bash command (database dumps, remote files).

## installation

```sh
git clone https://github.com/vielhuber/backuphelper.git
cd backuphelper
cp config.yaml.example config.yaml
```

## usage

```sh
./backuphelper.sh
./backuphelper.sh local remote
./backuphelper.sh --config /path/to/other.yaml
```

## configuration

```yaml
# every top level key is a job that writes <target>/<job>-YYYY-MM-DD-HHMMSS.tar.gz
local:
    sources:
        # every folder below path except skip; git checkouts only with untracked, ignored and modified files
        - type: git
          path: /var/www
          skip: [_environments, big-uploads]
        # a file or folder
        - type: path
          path: /var/lib/lamp
        # output of a bash command, stored as command-<position in this list> (here command-3)
        - type: command
          command: mysqldump --all-databases --single-transaction --routines --events --triggers
    # folder of the archives; the job is skipped while it is missing (e.g. an unplugged usb drive)
    target: /mnt/h/backuphelper
    # number of archives to keep
    keep: 14
    # optional: systemd calendar expression; omitted jobs only run manually
    schedule: '*-*-* 01:00:00'
    # optional: tar exclude patterns
    exclude: [node_modules, vendor, .cache, syncdb/cache]

remote:
    sources:
        # the password is passed via stdin, so it neither shows up in the remote command line nor in a process list
        - type: command
          command: |
              printf '%s\n' 'secret' | ssh -o BatchMode=yes user@example.com 'IFS= read -r MYSQL_PWD; export MYSQL_PWD; mysqldump --single-transaction -h localhost -u user database'
        - type: command
          command: ssh -o BatchMode=yes user@example.com 'tar -C www -cf - uploads || [ $? -eq 1 ]'
    target: /mnt/o/backups/remote
    keep: 7
    schedule: 'Sun *-*-* 00:30:00'
```

## scheduling

`schedule` uses systemd calendar syntax, not five-field cron syntax. For example, `*-*-* 01:00:00` runs daily at 01:00, `Sun *-*-* 00:30:00` on Sundays at 00:30, and `hourly` every full hour. Times use the machine's local timezone unless the expression includes a timezone.

Install or update the timers after changing the config:

```sh
sudo ./install-systemd.sh --user "$USER"
```

The installer creates one persistent timer per scheduled job and a shared service template. Missed appointments are caught up once when the timer is activated again, including after the computer was switched off. Backups can therefore also run during the day when a night appointment was missed. Timer activation does not wake a suspended computer.

Calls using the same config wait for each other, so scheduled and manual jobs run sequentially. Jobs without `schedule` have no timer. Direct calls to `backuphelper.sh` always run the selected jobs immediately, regardless of their schedule.

For a custom executor, pass the command after `--`; the installer appends `--config <file>` and the job name. The executor must accept those as separate arguments. For LAMP, which expects a single command string, install an executable wrapper such as `/usr/local/bin/backuphelper-lamp`:

```sh
#!/usr/bin/env bash
set -euo pipefail
printf -v command '%q ' /var/www/backuphelper/backuphelper.sh "$@"
exec /var/www/lamp/lamp exec backuphelper "$command"
```

```sh
sudo ./install-systemd.sh --config /var/www/backuphelper/config.yaml --user "$USER" -- /usr/local/bin/backuphelper-lamp
```

`--config /absolute/path.yaml` selects a different config. The config must be readable at that absolute path by the selected executor. One installation manages the `backuphelper@.service` template and `backuphelper-*.timer` units. Reinstalling removes obsolete timers generated by this installer and keeps their persistent timestamp history for remaining jobs. Running backup services are not restarted.

Inspect the next appointments with `systemctl list-timers 'backuphelper-*'` and a job's logs with `journalctl -u backuphelper@local.service`.

To migrate from `interval`, replace each interval with its desired calendar expression, disable the old cron entry or `backuphelper.timer`, and install the new timers. Legacy `interval` values are rejected rather than silently producing a backup on every invocation. Existing archives are retained.
